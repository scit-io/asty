# Locality-Aware Autoscaling

## Принцип

Запросы обрабатываются локально. Ресурсы используются максимально. Платформа всегда быстрая и отказоустойчивая.

## Базовая избыточность

- Минимум 3 копии каждого сервиса (type=service) в разных DC
- При падении базовой копии — немедленное восстановление без cooldown
- Восстановленная копия размещается в другом DC (geo-diversity)

## Gateway метрики — главный индикатор

Gateway на каждой ноде. Если Gateway принимает реальный трафик — на ноде должны быть сервисы. Юзер не должен ждать пока нагрузка "дорастёт до порога" — он уже получает +250ms из-за inter-DC hop.

### Фильтрация бот-трафика

Боты постоянно долбятся на все ноды. Если реагировать на любой запрос — autoscaler будет поднимать сервисы на каждой ноде без реальной потребности.

Двухуровневая защита:

**1. Gateway фильтрует метрики** — в счётчик valid_rps попадают только запросы:
- Прошедшие rate limiter (не заблокированные)
- С валидной сессией/токеном (authenticated)
- Бот-трафик (сканеры, crawlers, brute-force) отсекается на уровне Gateway и не попадает в метрики для autoscaler

**2. Порог RPS** — размещение сервиса срабатывает только при устойчивом потоке:
- Минимум 5 valid rps за скользящее окно 1 минута
- Единичные запросы от ботов, прошедших фильтр, не превышают порог
- Реальный пользователь генерирует устойчивый поток (страница, API-вызовы, WebSocket)

Параметры:
| Переменная | Описание | По умолчанию |
|---|---|---|
| `A_TRAFFIC_RPS_THRESHOLD` | Минимум valid rps для размещения | `5` |
| `A_TRAFFIC_WINDOW` | Скользящее окно оценки | `1m` |

## Scale UP

1. **Gateway valid трафик на ноде без сервиса** (>threshold rps, окно window) → поднять копию на этой ноде
2. **Процесс нагружен** (CPU >75% или Memory >75%) → добавить копию на ту же ноду (если есть ресурсы)
3. **Ресурсы ноды кончились** → ближайшая нода в том же DC
4. **DC заполнен** → ближайший DC по latency-матрице
5. **Несколько нод нагружены** → масштабировать параллельно на все

Несколько копий одного сервиса на одной ноде — нормально.

## Scale DOWN

1. Все процессы сервиса ниже target и count > min(3)
2. Удалять копии с наименее нагруженных нод
3. Сохранять geo-diversity (min=3 в разных DC)
4. Cooldown 5 минут между удалениями

## Параметры

| Параметр | Значение | Описание |
|---|---|---|
| Min copies | 3 | Базовая избыточность в разных DC |
| Max copies | unlimited | В рамках свободных ресурсов кластера |
| Target CPU | 75% | Порог для добавления копии |
| Target Memory | 75% | Порог для добавления копии |
| Traffic RPS threshold | 5 | Минимум valid rps для размещения |
| Traffic window | 1m | Скользящее окно оценки трафика |
| Cooldown UP | 30s | Агрессивное масштабирование |
| Cooldown DOWN | 5m | Осторожное уменьшение |
| Eval interval | 10s | Частота опроса метрик |

## DC proximity

Статичная latency-матрица в конфиге. Фоновые ping-замеры раз в час для валидации. При расхождении >50% — alert оператору. Используется конфиг, не runtime (защита от сетевых флуктуаций).
