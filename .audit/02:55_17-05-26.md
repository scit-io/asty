8. **Orchestrator `/metrics`** — Prometheus surface on `:8080`.

## 0. Summary

1. The pipeline does carry structured data end-to-end on the NATS
   side, but the API boundary collapses every record into a single
   display string. The browser then has no way to colour level,
   render time in the user's locale, or expand fields.
2. Two distinct string formatters do that collapse — one for the
   live SSE tail (`api/logs.go:47-68`) and one for the in-memory
   history buffer (`server/logbuffer.go:49-66`). They produce
   different strings from the same input, so the UI sees a
   discontinuity at the moment buffered history hands off to live
   tail.
3. Two NATS log subject trees carry two different JSON shapes:
   zerolog default JSON on `.logs.agent` / `asty.v1.server.logs`,
   and `LineFrame{line, timestamp}` on `.logs.<service>` where the
   agent wraps each tailed stdout line. After commit `8fbb31f` the
   wrapped content is itself zerolog JSON, so the wrapping is now
   pure overhead.
4. **Logs do not flow to Prometheus, and per project policy must
   not.** Recorded in [[project-logs-destinations]]: logs go to
   the dashboard SSE/buffer pair plus an external log shipper
   (Vector/Datadog/Loki). The CLAUDE.md mirror rule applies to
   metrics, not to logs. Section 1.3 below records the earlier
   draft of this audit incorrectly proposed adding log counters
   to `/metrics`; that proposal is retracted.
5. Smaller defects (duplicate types, duplicate timestamp fields,
   stringly-typed responses, dead fields, missing log-level honouring
   in demo services) all fold into the canonical-format work.
6. The dashboard styling pass must work in both light and dark
   themes — using existing Tailwind theme tokens so the switch
   carries through.

## 1. Critical

### 1.1 Two divergent server-side string formatters for the same data `[ ]`

Live SSE path — `asty/internal/features/api/logs.go:47-68` (`formatLogEntry`):

- Time formatted as RFC3339 (server's clock, server's locale).
- Level in square brackets.
- Message.
- Extras `json.Marshal`-ed and appended as a tail.

Buffered history path — `asty/internal/server/logbuffer.go:49-66`
(`makeLogAppender`):

- Time as raw Unix seconds in decimal.
- Level in square brackets.
- Message.
- Extras dropped entirely.

Both feed strings to the same `LogsView` component. The user
observes a discontinuity when the buffered prefix ends and the live
tail begins.

**Action:** delete both formatters once the canonical structured
entry exists; both paths emit the canonical object. See plan §5.B.

### 1.2 Structured data lossy-flattened to a string at the API boundary `[ ]`

`api/logs.go:96-98` shows the cliff: the pipeline carries a typed
`ZerologEntry{Level, Message, Time, Timestamp, Extras}` all the way
from `DecodeZerologEntry` (`entry.go:42-67`) — and then immediately
collapses it back into `LineFrame{Line: <stringified>, Timestamp}`
before the SSE frame leaves the server. The buffered-history path
does the same at `logbuffer.go:63-64`.

Downstream cost: the browser cannot colour the level (it's a
substring at a format-dependent offset), cannot render the timestamp
in the user's locale (already pre-baked to RFC3339 on the server),
and cannot show structured fields as a key/value panel (Extras is a
JSON tail concatenated into the line, or dropped).

**Action:** SSE emits the typed entry; buffer stores it; snapshot
API returns it. See plan §5.B.

### 1.3 ~~No Prometheus mirror for the log pipeline~~ — RETRACTED `[+]`

Earlier draft of this finding proposed adding
`asty_logs_total{level, source}` and
`asty_logs_decode_failures_total` counters to `/metrics`.

**Retracted.** User clarified (2026-05-17) that logs are not a
Prometheus surface in this project. Logs flow to two consumers:
the dashboard SSE/buffer pair, and an external log shipper
(Vector, Datadog, Loki) configured per deployment. Counters
derived from log content are the log shipper's job — Prometheus
is for metrics, not for derived log statistics. The mirror rule
(`UI ↔ Prometheus stay in lockstep`) applies to metrics, not to
logs.

The fact recorded for posterity: `:8080/metrics` does not expose
any log-related instruments today. Per the project policy, it
should not — there's nothing to mirror. Treat this section as
closed, not open.

See [[project-logs-destinations]] memory.

## 2. High

### 2.1 Two near-identical types for one log entry `[ ]`

`features/observability/logs/entry.go:13-16` — `LineFrame{Line string,
Timestamp int64}` with JSON tags `line`,`timestamp`.

`features/observability/logs/buffer.go:9-14` — `LogLine{Timestamp
int64, Level string, Line string}` with JSON tags `ts`,`level`,`line`.

Same conceptual data; different field order, different JSON tag
spelling (`ts` vs `timestamp`). They exist in parallel because the
format was never unified.

**Action:** collapse into one canonical entry type during phase A.

### 2.2 Two wire shapes on the log subjects `[ ]`

NATS publishes on two trees:

- `asty.v1.server.logs` and `asty.v1.agent.<id>.logs.agent` — zerolog
  default JSON, forwarded verbatim by `NATSWriter`
  (`nats_writer.go:28-33`).
- `asty.v1.agent.<id>.logs.<serviceName>` — `LineFrame{line,
  timestamp}`, produced by `agent/logstream.go:55-58` wrapping each
  line read from the per-process log file.

The server-side decoder reconstructs both via `DecodeZerologEntry`
+ `AsLineFrame` (`entry.go:75-88`). `AsLineFrame`'s heuristic — "no
level, no message, exactly one extra named `line`" — works today but
is fragile: a real zerolog event with a single field named `line`
would be misclassified.

After commit `8fbb31f` the bytes inside `LineFrame.line` are
themselves zerolog JSON. The wrap is overhead.

**Action:** publish the inner JSON verbatim; remove the wrap; remove
`LineFrame`; remove `AsLineFrame`. See plan §5.A.

### 2.3 Duplicate timestamp fields in every zerolog event `[ ]`

`asty/cmd/main.go:25-26` sets `zerolog.TimeFieldFormat =
TimeFormatUnix` and hooks `TimestampHook`. zerolog's package-default
global logger already adds `time` via its built-in `.Timestamp()`
behaviour (visible by the fact `entry.go:54` reads `time` from the
parsed map). `TimestampHook` (`timestamp_hook.go:20-22`) then adds
`timestamp` carrying the same Unix-second value.

The decoder reads both (entry.go:54-59) but downstream only uses
`Timestamp`. `entry.go:25-26` comments `Time` as "kept for
completeness".

**Action:** drop the hook (and the duplicate field). One source of
truth for time. Folds into phase A.

### 2.4 Orchestrator stderr writer wiring is unusual `[ ]`

`asty/internal/agent/agent.go:137` and `asty/internal/server/boot.go:100`
both rewire the global logger:

```text
log.Logger = log.Output(io.MultiWriter(log.Logger, natsWriter))
```

The same `log.Logger` is used as both the source of the new logger
and one of the destinations of the MultiWriter. zerolog's
`Logger.Write([]byte)` re-emits incoming bytes as a new event with
the bytes as message text (per the rs/zerolog source). The exact
runtime effect on terminal output deserves a careful look — at face
value this can cause each event to be ConsoleWriter-formatted twice
on stderr.

The NATS side is fine: `natsWriter` receives the original event
bytes and publishes verbatim.

**Action:** verify the actual terminal output, and if double-wrap is
confirmed, untangle the wiring (one writer for stderr, one for NATS,
no self-reference). Folds into the writer-side cleanup in phase A.

### 2.5 Allocation snapshot RPC ships opaque strings `[ ]`

`asty/internal/core/types/commands.go:72-76` — `LogsResponse.Logs
[]string`. `asty/internal/agent/commands.go:147-152` —
`handleLogsCommand` splits the per-process log file on newlines,
trims empties, returns the list of strings.

After commit `8fbb31f` each "string" is itself zerolog JSON. The
wire type does not say so; the consumer either parses each item as
JSON or treats it as opaque text. The HTTP snapshot
(`api/logs_allocation.go:70`) exposes this directly as `logs:
[<string>, ...]`.

**Action:** ship `[]Entry` (canonical type) on this RPC and surface
the same shape over HTTP. See plan §5.B.

## 3. Medium

### 3.1 Dashboard log styling must read well in light and dark themes `[ ]`

Today `LogsView` (`logs-view.tsx:80-90`) renders every line as plain
text in a single muted-background block. After the canonical-format
work the view should render rows of (time, level, message, fields):

- Time cell — locale-aware via `Intl.DateTimeFormat`, full RFC3339
  in a tooltip.
- Level cell — coloured pill using Tailwind theme tokens (`muted`,
  `primary`, `destructive`, `foreground`) so light/dark switch
  works automatically.
- Message cell — monospace, truncated to one line, expand on click.
- Fields cell — collapsed "N fields" chip; click reveals a small
  key/value panel.

Spot-check contrast under both themes — debug/info are the easiest
to lose under one theme or the other. Use only theme tokens, no
hard-coded hex.

**Action:** plan §5.C.

### 3.2 `LogLine.Level` is set in the buffer but never read `[ ]`

`server/logbuffer.go:64` writes `Level: e.Level` into the buffer
record alongside the already-formatted `Line` that contains the
level in brackets. The handlers (`api/logs_cluster.go:18-20`,
`api/logs_node.go:23-25`, `api/logs.go:113-117`) read only `.Line`
and `.Timestamp`. Dead field.

**Action:** falls out with the type unification.

### 3.3 `formatLogEntry` fixes timestamp display to RFC3339 server-side `[ ]`

`api/logs.go:56-58`. Pre-baking the format denies the browser its
choice of locale and relative-time rendering. After the format
unification the wire carries the numeric timestamp and the browser
decides.

### 3.4 `streamFromNATS`'s `fallthroughOnParse` parameter is a tell `[ ]`

`api/logs.go:86`. Only `logs_allocation.go:39` sets it to `true`,
because allocation logs are `LineFrame` not zerolog —
`DecodeZerologEntry` succeeds on them only via the `AsLineFrame`
recovery, and parse failures (very early in startup, malformed bytes)
need a fallback. Once the wire is unified, parse failures become
metrics instead of fallback behaviour, and the parameter disappears.

### 3.5 Frontend types are stringly-typed for logs `[ ]`

`asty/web/src/types/index.ts:64` — `AllocationDetail.logs?: string[]`.
The implicit shape of the JSON snapshot responses (`logs: string[]`)
flows from the Go side's `[]string`. After the wire becomes
canonical entries, the TS type becomes `LogEntry[]`.

### 3.6 `LogsView` swallows malformed frames silently `[ ]`

`logs-view.tsx:51-53` — empty `catch`. Acceptable today because
every frame is well-formed JSON; during the format migration it can
hide schema drift. A one-line `console.warn` (or a "schema error"
pill) helps catch issues during the transition.

### 3.7 No active-subscribers gauge for log streams `[ ]`

Operationally useful (detect leaked dashboard tabs, understand
load), trivially cheap (one `Inc`/`Dec` around the subscription in
`api/logs.go:streamFromNATS`). Not mandated by the mirror rule —
nothing on the dashboard currently shows it — but worth adding
during the Prometheus work in §5.E since the code spot is exactly
where the unification lands.

## 5. Refactor plan

### Phase A — canonical wire shape

**A.1** Define a single `Entry` type in
`features/observability/logs` with JSON tags `time`, `level`,
`message`, `fields`. Replace `ZerologEntry`, `LineFrame`, and
`LogLine` with this single shape. `[ ]`

**A.2** Drop `TimestampHook`. Rely on zerolog's default `time` field
(no second source of truth). `[ ]`

**A.3** Agent's `streamProcessLogs` publishes the tailed line
verbatim if it parses as JSON; otherwise wraps into an `Entry` with
`{level: info, message: <raw>, time: now}`. No more `LineFrame`. `[ ]`

**A.4** Untangle the orchestrator stderr writer wiring (task 2.4):
one writer for stderr, one for NATS, no `log.Logger` self-reference
in `io.MultiWriter`. `[ ]`

### Phase B — collapse server-side formatters and add the mirror

**B.1** Delete `formatLogEntry` (`api/logs.go:47-68`) and the
formatter inside `makeLogAppender` (`server/logbuffer.go:49-66`).
Buffer holds `Entry`; SSE emits `Entry`; snapshot returns
`[]Entry`. `[ ]`

**B.2** Drop the `fallthroughOnParse` parameter on
`streamFromNATS`. `[ ]`

**B.3** `types.LogsResponse.Logs` becomes `[]logs.Entry`. Agent's
`handleLogsCommand` decodes each line into an `Entry` and ships the
list. `[ ]`

~~**B.4** Register Prometheus instruments for log events.~~
**Removed** — logs are not on the Prometheus surface in this
project. See retracted §1.3 and [[project-logs-destinations]].

### Phase C — frontend

**C.1** Add `interface LogEntry { time: number; level?: string;
message: string; fields?: Record<string, unknown> }` to
`asty/web/src/types/index.ts`. Replace `logs: string[]` with
`logs: LogEntry[]`. `[ ]`

**C.2** Refactor `LogsView` to render rows of (time, level, message,
fields). Use Tailwind theme tokens (`muted-foreground`, `primary`,
`destructive`, …) for the level pill so light/dark themes carry
through. `[ ]`

**C.3** Drop the `data.line ?? JSON.stringify(data)` fallback in
`logs-view.tsx:43`. `[ ]`

**C.4** Replace the silent `catch` in `logs-view.tsx:51-53` with
`console.warn` and a small inline "schema error" pill. `[ ]`

**C.5** Verify contrast and palette under both light and dark
themes. Pay attention to debug/info — they're the easiest to lose
under one theme or the other. `[ ]`

### Phase D — clean-up

**D.1** Demo services read `A_LOG_LEVEL` and call
`zerolog.SetGlobalLevel`. `[ ]`

**D.2** Decide on the timestamp encoding: keep Unix seconds or
move to zerolog's RFC3339Nano default. Whichever is chosen, set it

**D.3** Refresh the comment on `NATSWriter` to match the new

### ~~Phase E~~ — Prometheus tile in the UI — REMOVED

Logs do not flow to Prometheus in this project — see

## 8. What's good (anchor)

- `NATSWriter.Write` is zero-copy: zerolog emits JSON, the writer
  publishes the bytes to NATS verbatim. Composition with stderr via
  `io.MultiWriter` is idiomatic — only the `log.Logger`
  self-reference inside the MultiWriter (task 2.4) is suspect.
- `DecodeZerologEntry` separates known fields from `Extras` using
  `map[string]json.RawMessage`. The shape is right; only the
  downstream collapse to string is wrong.
- The reconnect-with-backoff in `LogsView` (`logs-view.tsx:55-61`)
  is solid and survives both server restarts and network blips.
- Ring buffer + `GetLast(n)` is a clean, bounded-memory history
  store. No change needed at the storage layer beyond the entry
  type.
- The per-process log file with optional rotation
  (`features/execution/process/logs.go`) is a sound foundation. The
  format change to JSONL doesn't affect rotation behaviour.
- Six Prometheus collectors already follow the mirror rule for the
  cluster/node/alloc/service/deploy/NATS surfaces — the log
  pipeline just hasn't joined them yet. The pattern to extend is
  in place.
