# Asty Web Dashboard — Deep Refactor Plan

Scope: `asty/web/src` (the React SPA only). 38 non-UI source files,
~4 780 lines, branch `main` at `25aac66`. Goal stated by the user:
no hardcode, no copy-paste, maximum reuse, every page nests under
the right folder, the markup must not change a single pixel and no
data must be lost.

This is an audit-format plan. Tasks use the marker convention:

- `[ ]` not started
- `[~]` in progress
- `[+]` done

Sections are sorted by priority; **the actual work order is in §5
Refactor plan** (phases A → E).

---

## 0. Top summary

1. The **store is one 766-line file** (`store/cluster.ts`) that owns
   every resource, every SSE wiring, every poller. It must be split
   per resource (cluster / nodes / services / allocations) with a
   shared streaming layer.
2. **URL strings are smeared across 20 files** — page navigation,
   API calls and SSE subjects all build paths with raw template
   literals. A single `lib/routes.ts` should be the only producer
   of `/nodes/...` / `/services/...` strings; `api/client.ts` should
   consume it too.
3. **The page wrapper is copy-pasted 16 times** — every page opens
   with one of two `<div className="container mx-auto …">` variants.
   One `<PageShell>` (with a `tall` flag for the logs viewport
   variant) replaces all of them.
4. **Tab arrays repeat verbatim 12 times** — Node tabs (4×), Service
   tabs (4×), Allocation tabs (2×), Cluster section tabs (3× via
   re-export). Move to per-section `tabs.ts` next to the pages they
   describe.
5. **`statusVariant` / `healthVariant` are re-declared 4 times** for
   nodes / allocations / deploys. One `lib/variants.ts` consolidates
   them.
6. **The allocation Restart/Stop flow is duplicated in 3 pages**
   (node alloc list, service alloc list, alloc detail). Extract a
   `useAllocationActions` hook that owns the pending map, the toast
   wording and the post-stop navigation.
7. **Magic numbers are scattered** — store has `60`, `100`, `10`,
   `3000`, `60000`, `15000`; `LogsView` has its own `1000`, `150`,
   `40`, `3000`, `60000`. Collect into `lib/constants.ts` so the
   reconnect/backoff numbers and chart-window constants live in one
   place.
8. **Service Overview is 345 lines** of inline cards (configuration
   table, min-copies card, deploy card, last-action chooser). Each
   of those is a self-contained block that belongs in its own file
   under `features/services/`.
9. **`useClusterStore()` is called without selectors** in 7 pages,
   so each page re-renders on every store mutation regardless of
   what it actually reads. Selector-form everywhere is a one-line
   change with measurable wins.
10. **One naming nit**: `pages/cluster/overview.tsx` is the
    section landing for `/`, but the matching landing for `/services`
    is `pages/services/index.tsx`. Unify to `index.tsx`.
11. **Verstka rule.** Every refactor below is layout-neutral.
    Classes, grid arrangements, breakpoints, colours stay byte-for-
    byte. The only acceptable diff in a `git diff -w -- "*.tsx"`
    after Phase A is import paths and shorthand collapses. Verify
    visually with `npm run dev` after every phase.

## 1. Critical

### 1.1 Demo-service artefacts inside `asty/` [+]

`grep -niE "xauth|xhttp|xws|demo" asty/web/src/**/*.{ts,tsx,html,css}`
returns exactly one match: `types/index.ts:147`, in a comment listing
example component-label values (`server | agent | gateway | xauth | …`)
for `LogEvent.component`. That value comes from the wire, not from
hardcoded SPA logic; the comment is generic enough to read as
illustrative. **Verified clean** — the dashboard makes no service-
specific assumption in code.

### 1.2 Format-discipline boundary check [+]

All `JSON.parse` / `JSON.stringify` calls in the SPA sit on legitimate
boundaries: SSE deserialisation in `store/cluster.ts` (15 sites),
parser fallback in `components/logs-format.ts`, log-field stringify
in `components/logs-view.tsx`, and four `fetch.body` builders in
`api/client.ts`. **Verified clean** — no internal-state JSON outside
those boundaries.

### 1.3 Cyrillic in source [+]

`grep -rcE "[А-Яа-я]" asty/web/src --include="*.{ts,tsx}"` returns
zero hits. **Verified clean.**

### 1.4 `pendingUpdates` / `flushTimer` are module-level globals [+]

`store/cluster.ts:218-241` — both the batched-update queue and the
debounce timer live at module scope. If zustand is ever re-created
(HMR, tests), the leftover queue applies to the new store via the
captured `set` — a stale closure. Pull both into the `create(...)`
callback so each store instance has its own batch state.

**Action:** Move declarations to the top of the factory body
(`create((set) => { let pendingUpdates = []; … return { … } })`);
update `scheduleSet` to be a closure over them.

### 1.5 `subscribeService`'s deploy SSE bypasses the reconnect lifecycle [+]

`store/cluster.ts:585` opens `deployES = new EventSource(...)`
directly instead of going through `openStream`. Consequences:

- no exponential backoff on disconnect,
- no `'dead'` terminal state after `STREAM_MAX_RETRIES`,
- no state-driven cache wipe on connection loss,
- divergent error semantics from the four siblings.

The progress event needs the `set` closure (the same as the rest),
so the fix is one extra `openStream` call with its own `onState` —
not a separate code path.

**Action:** wrap with `openStream(`${API_PREFIX}/services/${name}/deploy`, …)`
inside the same `subscribeService` cleanup compose; remove the bare
EventSource branch and its standalone `historyCancelled` flag.

## 2. High — the refactor itself

### 2.1 `store/cluster.ts` is 766 lines and owns every resource [+]

The file mixes:

- a shared SSE-lifecycle helper (`openStream`),
- a shared `set`-batching layer (`scheduleSet`, `pendingUpdates`),
- a global cluster overview (`subscribeCluster`),
- per-resource caches (nodes / services / allocations),
- six `subscribeXxx` methods,
- an autoscaler poller,
- a deploy SSE,
- a deploy-versions fetch,
- an optimistic `updateNodeStatus`,
- and a `refreshService` mutation helper.

Split:

```
store/
  index.ts              re-exports useClusterStore, derives selectors
  stream.ts             openStream, scheduleSet, attachStatusHandler, types
  slices/
    cluster.ts          clusterStatus + clusterCpu/Memory/Rps + subscribeCluster
    nodes.ts            nodes[] + nodeCache + subscribeNodes/subscribeNode + updateNodeStatus
    services.ts         services[] + serviceCache + subscribeServices/subscribeService + refreshService
    allocations.ts      allocationCache + subscribeAllocation
```

A single `useClusterStore = create(combine(...slices))` keeps one
zustand instance; pages keep importing one symbol. Each slice file
stays under the 200-line cap and reads top-to-bottom as "what is
this resource and how do we keep it fresh".

**Action:** stage in PR-sized chunks: stream helpers first
(non-functional), then one slice at a time. Each migration is
"move + replace import", no behaviour change.

### 2.2 URL strings live in 20 files [+]

`grep -rnE "/(services|nodes)/\\\${"` finds **38 occurrences**
across pages, headers, the API client and the store. Each one is a
chance to mistype a segment.

Add `src/lib/routes.ts`:

  clusterLogs: '/logs',
  nodes: '/nodes',
  node: (id: string) => `/nodes/${id}`,
  nodeAllocations: (id: string) => `/nodes/${id}/allocations`,
  nodeLogs: (id: string) => `/nodes/${id}/logs`,

    `/nodes/${nodeId}/allocations/${allocId}`,
  allocationLogs: (nodeId: string, allocId: string) =>
    `/nodes/${nodeId}/allocations/${allocId}/logs`,
  services: '/services',
  service: (name: string) => `/services/${name}`,
  serviceAllocations: (name: string) => `/services/${name}/allocations`,
  serviceAutoscaler: (name: string) => `/services/${name}/autoscaler`,
  serviceDeploy: (name: string) => `/services/${name}/deploy`,

Add `src/lib/api-paths.ts` mirroring routes under `API_PREFIX`

`<Link to={…}>`, `navigate(…)`, breadcrumb `to`, tab `to`.

**Action:** add the file, refactor `api/client.ts` first (smallest
blast radius), then headers, then pages.

### 2.13 `useClusterStore()` without selectors in 7 pages [ ]

```ts

```

## 5. Refactor plan

Each phase is **one mergeable PR**. Phases are sequential — Phase B
depends on Phase A's `lib/routes.ts` for some moves, Phase C on
Phase B's slice boundaries for cleaner imports, etc. Within a
phase, tasks can land in any order.

After every phase: `npm run dev`, click through every page, confirm
no visual diff against the previous main. Take a screenshot per
section if the team wants a paper trail.

       to use it. Extended to cover all API path consumers in one
       sweep: `store/cluster.ts` (7 SSE URLs) and the 3 logs pages

## 6. Not-defects (head off "why didn't you catch X?")

### 6.1 `Tile` is correctly a single component with variants [ ]

The `variant: 'metric' | 'stat' | 'timestamp' | 'actions'`
discriminator (`components/tile.tsx`) earns its place — the
top/bottom anchoring logic is shared across all four variants and
splitting per variant would force callers to import 4 components
or duplicate the alignment classes. Leave as-is.

### 6.2 `DataTable` is correctly generic [ ]

The single 191-line component handles search + sort + pagination
for all four list pages. Its callers pass column configs that vary
slightly but the table itself has no per-page branching. No need
to split.

### 6.3 `MetricsChart` is intentionally self-contained [ ]

uPlot lifecycle, theme reactivity and ResizeObserver are tightly
coupled to one chart instance per card; the 171-LOC file is a
single feature with no exports beyond `MetricsChart`. Leave as a
unit.

### 6.4 No tests — left out of scope on purpose [ ]

The SPA has zero `*.test.tsx` files today. Adding Vitest + RTL
is a separate decision (it touches `package.json`, `tsconfig`,
CI). This plan deliberately doesn't bundle it: refactoring without
tests works when each phase is verified by `npm run dev` + click-
through, and tests added afterwards lock in the new shape rather
than the old. Raise as a follow-up if the team wants it.

### 6.5 The "navigate('/nodes') after stop" UX is intentional [ ]

The current code redirects to `/nodes` after a Stop on any of the
three allocation pages. Reasoning: stop deletes the slot, the
reconciler backfills on a different node, the current page would
404. Keep the behaviour in the extracted `useAllocationActions`
hook.

### 6.6 `useClusterStore()` without selector ≠ broken [ ]

The pages still render correctly today. §2.13 is a perf-and-
cleanliness fix, not a correctness fix. Listed as High because
it's cheap and reads well as part of the refactor wave; not
Critical.

## 8. What's good — anchor as standard

Plenty of decisions in the SPA are already clean. Keep them; the
refactor should make them more visible, not undo them.

- **Page hierarchy already mirrors URLs.** `pages/cluster/nodes/[nodeId]/
  allocations/[allocId]/overview.tsx` reads as a route and matches
  the React Router path 1:1. The only inconsistency is §3.5.
- **One SSE per page.** `subscribeXxx` returns a cleanup; pages
  call it inside `useEffect`. No double-subscriptions, no leaks
  on tab-switch.
- **Single `EventSource` lifecycle helper.** `openStream` covers
  connecting/streaming/reconnecting/dead states with exponential
  backoff and onState-driven cache wipes. The only deviation is
  the deploy SSE in §1.5 — fix it, then this becomes universal.
- **Reusable `<DataTable>`.** All four list pages share one table
  with search/sort/pagination — no per-page reimplementation.
- **`<Tile variant>` covers four card shapes** with consistent
  baseline alignment (the `Top`/`Bottom` flex anchoring is one of
  the nicer ideas in the codebase).
- **Header/Navigation/Breadcrumbs/Tabs** already extracted into
  reusable components (`Breadcrumbs`, `ResourceTabs`, `NodeHeader`,
  `ServiceHeader`, `AllocationHeader`). The refactor's job is to
  feed them less inlined data — not to recreate them.
- **Format helpers** (`formatMB`, `formatMHz`, `formatPercent`,
  `formatCount`, `uptimeLabel`) are already centralised in `lib/`
  and used universally. New refactor work follows the same pattern.
- **Themed via CSS variables**, charts re-create on theme flip via
  `MutationObserver` on `<html class>` — robust and stays untouched.
- **No `any`, very few `as unknown as X`** — the type discipline
  in `types/index.ts` mirrors the Go side's shape and the SPA
  doesn't fight it.

These are the standards the refactor should preserve. The work
above is about pulling the next 20% of duplication out so the next
person to add a page has even fewer copies to make.
