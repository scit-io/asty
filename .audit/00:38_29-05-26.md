## 0. Top summary

- **One real format-discipline regression.** `asty.v1.scaling.event`
  is published with `json.Marshal` and decoded with `json.Unmarshal`
  on the consumer; every other internal-only NATS subject goes through
  `codec.Wire` (CBOR). It does not flow to SSE, so the documented
  `deploy.progress` / `drain.progress` carve-out does not apply.
- **Demo names leak into `asty/` test fixtures and web comments.**
  Per CLAUDE.md "Any leakage is a Critical defect." Rate-limiter
  tests hard-code `/v1/auth/*`; a log-parser test fixture is keyed by
  `"component":"xws"`; web TS comments and a logs-page tooltip name
  `xauth` as a concrete example.
- **`NodeDiscovery.WatchNodes` is observability-only.** Started in
  `server/leadership.go:32-39`, polls DNS every 15 s, and its
  `onChange` callback only writes one log line. The real peer
  source for the cluster is `agent/natswatch.go`. Either rename it
  to `logClusterNodes` and accept the cost, or delete the package
  and its boot wiring.
- **One hot-path N+1 in snapshot.** `streamHub.buildSnapshot` calls
  `deployer.GetHistory()` (returns up to 100 records, all copied)
  once per service inside the loop at `server/snapshot.go:193`.
  Snapshots fire on every debounced KV event; a pre-built
  `lastDeployByService` map removes the quadratic.
- **`cap` is shadowed by local variables** in
  `ops/autoscaler/scale_up.go:29` and `api/dashboard/services.go:119`.
  Legal but flagged by `go vet -vettool` with the `shadow` checker;
  fix is renaming to `maxCopies`.
- **Dead alias.** `var mustJSON = types.MustJSON` in
  `api/dashboard/api.go:188` has zero call sites.
- **`realIP` is duplicated** between `gateway/middleware.go:60` (full
  X-Real-IP + TrustedProxy support) and `api/dashboard/audit.go:138`
  (RemoteAddr-only, with an inline `// We don't have cfg here` admission).
  Operators behind a trusted proxy get correct rate-limit attribution but
  wrong audit `ActorIP`.
- **Six files over the 200-line cap.** Same list CLAUDE.md
  acknowledges as deferred; calling it out so the next refactor
  inherits the punch list.
- **Coding-rules docs drift.** `.claude/coding-rules/architecture.md`
  and `.claude/coding-rules/file-layout.md` still reference the
  `features/` directory layout, which was replaced by the L0..L4
  onion (`core/infra/domain/ops/api`) recorded in `CLAUDE.md`.
  Audit findings must be able to cite a current rule.
- **Event-driven posture is clean.** Every `time.NewTicker` site is
  on the documented allow-list or is an SSE/WS-protocol keepalive.
  No `time.Tick` / blind `time.Sleep` loops outside the documented
  exponential-backoff helpers in `core/netutil`.

### 1.2 Format discipline — `asty.v1.scaling.event` is JSON, should be CBOR [+]

The project rule (binary-first; CLAUDE.md & `core/codec/codec.go`)
says internal NATS subjects use `codec.Wire`. Two documented
carve-outs exist for `asty.v1.deploy.progress.*` and
`asty.v1.drain.progress` — both fan straight out to SSE so a CBOR-to-
JSON re-encode at the SSE boundary would be wasted work
(`ops/deployer/history.go:15-19` is explicit about this).

`asty.v1.scaling.event` does not flow to SSE. It is server-to-server
distribution; the dashboard reads from the in-memory
`metricsStore.GetEvents` ring at HTTP request time. Yet:

- `ops/autoscaler/metrics/store.go:87` — `json.Marshal(evt)`
- `server/metrics.go:46-52` — `json.Unmarshal(msg.Data, &evt)`

`server/metrics.go` already uses `codec.Wire` for the neighbouring
`subscribeGatewayMetrics`; the asymmetry is a previous-iteration
oversight, not a deliberate carve-out.

**Action:** swap `json.Marshal` → `codec.Wire.Marshal` at
`store.go:87`, `json.Unmarshal` → `codec.Wire.Unmarshal` at
`metrics.go:48`. Document the choice with a short comment matching
the existing carve-out comment in `history.go`.

## 2. High

### 2.1 `buildSnapshot` calls `GetHistory()` once per service [+]

`server/snapshot.go:193-201`:

```go
for _, rec := range h.server.deployer.GetHistory() {
    if rec.Service != svc.Name { continue }
    ...
    break
}
```

`GetHistory()` itself (`ops/deployer/history.go:130-139`) copies up to
`historyCap = 100` records under the deployer mutex AND reverses them
into a new slice. The snapshot loop walks every service definition
(today ~3; can grow to dozens), so each rebuild does N copies of a
100-element ring + N×100 string compares — held against the
streamHub debounce that fires aggressively on KV bursts.

**Action:** build the lookup once before the service loop:

```go
historyByService := map[string]*deployer.DeploymentRecord{}
for i, rec := range h.server.deployer.GetHistory() {
    if _, seen := historyByService[rec.Service]; !seen {
        historyByService[rec.Service] = &rec
        if len(historyByService) == len(services) { break }
    }
}
```

then read `historyByService[svc.Name]` inside the per-service block.

### 2.2 `NodeDiscovery` is log-only [+]

`ops/discovery/discovery.go` polls DNS every 15 s and fires
`onChange(nodes)` when the IP set changes. The single caller —
`server/leadership.go:32-39` — supplies an `onChange` that *only logs*:

```go
func (s *Server) watchClusterNodes(ctx context.Context) {
    s.nodeDiscovery.WatchNodes(ctx, func(nodes []string) {
        log.Info().Strs("nodes", nodes).Int("count", len(nodes)).
            Msg("cluster nodes updated")
    })
}
```

The real source of cluster membership is `cluster KV` (server reads
node KV entries; the leader's snapshot uses these). NATS peer
discovery for the supervised broker has its own path
(`agent/natswatch.go`, 5 s ticker). So this package exists to power
one informational log line per DNS change.

Three options, listed for the user to pick:

**Variant 1:** delete the package + the field + the goroutine. The
log line is replaceable by a single line inside `watchNATSPeers`'
`if changed { … }` branch (which already detects the same event,
five times more responsively).

**Variant 2:** rename the function to `logClusterNodeChanges` and
keep it; cheaper than the watcher cost in dev, useless in prod with
short DNS TTLs.

**Variant 3:** wire `onChange` into something real (e.g. seed a
"projected nodes" metric, or notify the discovery cache the gateway
queries). Largest scope; probably out of band for this audit.

**Recommendation:** variant 1 — the data is duplicated and the
caller's intent is already captured by `watchNATSPeers`.

`api/dashboard/services.go:119`:


`grep -rn 'mustJSON\b' asty/internal` returns only the declaration.

### 2.5 `realIP` duplicated, audit-side is incomplete [+]

`api/gateway/middleware.go:60-76` — full implementation: parses
`X-Real-IP` only when `RemoteAddr` matches `cfg.RateLimit.TrustedProxy`,
falls back cleanly.

`api/dashboard/audit.go:138-147` — same function name, RemoteAddr-only.
The comment is unusually candid: `// We don't have cfg here; keep it
simple — RemoteAddr is the truthful source unless a future change
wires the trusted-proxy list into the audit middleware.`

Result: when operators sit behind a configured trusted proxy, the
rate-limiter sees real client IPs but every audit event records
the proxy. ActorIP is one of the most-checked fields in an audit log.

**Action:** plumb the gateway config (or just `TrustedProxy`) into
the dashboard `API` so `audit.go` can call the gateway version.
Either factor `realIP` out to `core/netutil`, or expose
`gateway.RealIP(r, trustedProxy)` as a thin re-export.

### 2.6 Unchecked `msg.Respond` errors in `agent/commands.go` [+]

NATS `msg.Respond` returns an error if the message has no `Reply`
or the connection is closed. Roughly 15 sites in
`agent/commands.go` ignore it — `errcheck` would flag each one.
`server/commands.go` is clean.

Example sites: 48, 56, 66, 70, 77, 87, 91, 98, 106, 120, 128, 145,
152, 170.

**Action:** prefix each with `_ = msg.Respond(...)` — the project
already uses the explicit-discard idiom elsewhere (see
`api/stream/sse.go` for `_ = w.Write`-style sites).

## 8. What's good — anchor as standard

- `core/codec/codec.go` is the textbook implementation of the
  binary-first rule: one switch in one file, `UseJSONForDev`
  flips both Wire and State together, dev/prod can't diverge.
- `server/streamhub_subs.go:subscribers[T]` collapses three
  mutex+map+nextID copies into one ~60-line generic — exactly the
  pattern code-idioms.md endorses.
- `kv/watch.go:watchKV` is the same pattern at the watcher layer.
  Adding a new KV watcher is now a 5-line wiring change.
- `core/codec` + `codec.Wire.Marshal/Unmarshal` are honoured by
  `gateway` reports and agent RPCs; `asty.v1.scaling.event` (§1.2)
  is the lone holdout, which is why §1.2 is fixable in two lines.
- Polling allow-list is exhaustively documented at every
  `time.NewTicker` site with a `// const intervalName — why N s`
  block. New tickers added without that comment would stand out
  in review.
- Tests live next to code, fixtures use typed enums (per
  `testing.md`), race-tested concurrent code paths (streamHub,
  scheduler, drainer).
- Prometheus collectors have an explicit "mirror rule" comment
  at the package head; gauges read straight from the streamHub
  snapshot so UI numbers and `/metrics` numbers cannot diverge.
- No `interface{}` in production source (all replaced with `any`).
- No `panic` anywhere except `ringbuf` capacity check (correctly
  treated as a programmer error).
